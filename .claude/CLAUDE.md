# CLAUDE.md — `arrmatura-books`

Guidance for Claude Code in this repo. The kit follows the module blueprint of `arrmatura-web`
(`~/Projects/arrmatura-web/.claude/CLAUDE.md`), which holds the CML and service idioms; they are
not repeated here.

## Summary

`arrmatura-books` is the docs-site kit: an `App` shell, `DocsTree`, `Quiz`, three services and
four overrides of `arrmatura-web/md`'s `MD*` components. It was the `modules/books` module of
`arrmatura-web` until 2026-09-26, when it moved here as its own package. A site registers it as
the app's own `components`:

```ts
import { components } from "arrmatura-books";
launchPlatformApp({ components });
```

⚠️ `components` is `Object.values(registry)`. Handing the module namespace over instead registers
each file's raw source under its export name — `createRegisterTypes` reads a plain object as
`{ tag: template }` and only walks an array element-wise.

Consumer: the `almaat` site (`~/Projects/almaat`).

## Layout

```
index.ts        # hand-written barrel: `export * from "./registry"`, the `components` array for
                #   launchPlatformApp, plus the siteTree helpers and types
registry.ts     # GENERATED — one named re-export per component; registered as Object.values()
catalog.json    # GENERATED — component signatures for the CML tooling
cml/            # App.xml, components/ (DocsSidebar, DocsTree*, Quiz), extensions/ (MD* overrides)
src/            # services (.ts) beside their <Signature kind="service"> stubs (.xml), siteTree.ts
scripts/        # codegen + esbuild, copied verbatim from arrmatura-web/scripts on 2026-09-26
```

One flat module: `cml/` and `src/` sit at the package root, and `scripts/index-module.ts` runs
the shared generator with `moduleDir: "."`.

## Dependencies

`arrmatura-web`, `arrmatura` and `ultimus` are peers, linked from the sibling checkouts by
`postinstall` (`scripts/link-modules.sh`). Services extend `WebClientService` from
`arrmatura-web/core` — the lean platform barrel — never from the root `arrmatura-web`, which
pulls in every `.xml`, mermaid and highlight.js. Everything the CML uses (`Bar`, `Btn`, `Icon`,
`MarkdownView`, `LocalStorage`, `NavigationService`, the plugins) comes from the platform bundle
that `launchPlatformApp` registers before this kit.

## ⚠️ Sync rules

- `registry.ts` and `catalog.json` are generated by `npm run codegen`, then formatted by the
  `postcodegen` hook. Never hand-edit them; re-run and commit the result.
- `registry.ts` is exempt from Biome's import organizer (`overrides` in `biome.json`): the
  generator's export-name order is the registration order, and the organizer would re-sort it
  by module path.
- A `<Name>.ts` beside a `<Name>.xml` makes it a service: the generator re-exports the class in
  place of the stub. Keep the stub's `id` equal to the class name.
- Every `.xml` declares one `<Component>`, named after the file — `MDLink.Book` lives in
  `MDLink.Book.xml`.
- Whenever a component or its `<Signature>` / `<Prop>` changes, regenerate `catalog.json` in the
  same change.

## How the `MD*` overrides win

`App` renders `<MarkdownView prefix="Book">`, so the renderer emits `MD*.Book` tags and the
registry falls back through dotted prefixes (`MDCode.Book` → `MDCode`). All four overrides are
declared under the suffixed tag (`MDSection.Book`, …), so they apply to that prefix only — a
`MarkdownView` without it keeps `md`'s defaults — and registration order plays no part.

⛔ Never declare an override under the plain tag (`MDSection`): it would replace `md`'s component
for every view on the page, and only while this kit is registered after the platform bundle.

`BookIndexTreeService` must be mounted as `Ref="bookIndex"`: `DocsTree` and `MDLink.Book` bind
`@bookIndex.*` by that literal name.

## Conventions

- Service loaders stay plain: `up({ loading: true })` → fetch → `up({ ...patch, loading: false })`.
  No deferred-skeleton timers, no request-sequence guards. URL templates use `*` as the placeholder
  (`resolveUrlPattern="/docs/*"`), not `{id}`.
- ⚠️ Unbraced attributes are literal strings: `disabled="!value"` is a truthy string, not an
  expression. Brace expressions (`disabled="{!value}"`). `If`, `Each`, `Slot`, `Key`, `As`,
  `Props`, `Ref` and `data-*` are compiled as expressions and must not be braced.
- No `@/` alias; inside the package imports are relative (`./src/X`, `./registry`).
